## 4.2 Implementasi dan Hasil Perangkat Keras (IoT)

Paragraf pembuka: uraikan 3 lapisan IoT dalam sistem ini:
- *Edge*: ESP32 + 2 flow sensor + pressure + INA219.
- *Network*: Wi-Fi 2.4 GHz, protokol MQTT & CoAP.
- *Application*: laptop (broker/server + dashboard).

### Tabel 4.1 — Alat & Bahan (SUDAH ADA di kerangka, tinggal pakai)
ESP32 DOIT DevKit V1, YF-S201 ×2, WPT-83G, INA219 (CJMCU-219), adaptor 5V, breadboard+jumper,
pipa PVC + T-junction. (lihat bab4-kerangka-revised.md)

### Tabel 4.2 — Library/Software
Arduino IDE, Adafruit INA219, PubSubClient (MQTT), coap-simple-library (CoAP),
Mosquitto (broker), aiocoap (CoAP server), Node-RED (dashboard).

### 4.2.1 Prosedur Perakitan Perangkat Keras
Format bernomor (rujuk `wiring-saat-ini.md`):
1. Siapkan komponen (gambar tiap komponen).
2. Jalur daya: adaptor 5V → rail +/− breadboard; common ground ke ESP32.
3. Sambung sensor ke ESP32:
   - Flow1 → GPIO25 (langsung, INPUT_PULLUP)
   - Flow2 → GPIO27 (langsung, INPUT_PULLUP)
   - Pressure → voltage divider 20K/10K → GPIO34 (ADC)
   - INA219 → SDA GPIO21, SCL GPIO22, VCC 3V3
4. Pasang sensor pada pipa (Flow1 → T-junction → Pressure → Flow2).
5. Hubungkan ESP32 ke laptop via USB; nyalakan.
- Rujuk Gambar: diagram wiring & rail 5V (folder diagrams).
- Catatan teknis (dari log): Flow sensor TIDAK pakai divider (open-collector); GPIO34
  input-only; voltage divider WAJIB untuk pressure (output >3.3V).

### 4.2.2 Prosedur Pengembangan Firmware ESP32
1. Setup Arduino IDE + board ESP32.
2. Baca sensor: flow via interrupt (pulsa), pressure via ADC, INA219 via I2C.
3. Susun payload JSON tunggal (pengaman nan/inf → 0 agar JSON valid).
4. Kirim via MQTT (publish) dan CoAP (PUT) — payload identik.
- Catatan: trik BOOT saat upload (board DOIT V1 tidak auto download-mode).

### 4.2.3 Prosedur Penyiapan Gateway (Laptop)
1. Broker MQTT Mosquitto (config `listener 1883 0.0.0.0`, firewall port 1883).
2. CoAP server aiocoap (resource `/sensor`, port 5683 UDP, firewall).
3. Node-RED untuk dashboard (opsional jembatan CoAP).

## 4.4 Implementasi Komunikasi MQTT dan CoAP (SUDAH JALAN)

Paragraf pembuka: data sensor identik dikirim via dua protokol untuk dibandingkan.

### 4.4.1 Implementasi MQTT
- Model publish-subscribe (TCP). Broker Mosquitto di laptop, port 1883.
- ESP32 (PubSubClient) publish JSON ke topik `smartwater/data`.
- Bukti: broker menerima pesan; subscriber menampilkan data (end-to-end terbukti). ✅
- Isu & solusi (bahan pembahasan): IP broker dinamis, client ID unik, keepalive,
  `listener 0.0.0.0`. (rujuk `setup-mqtt.md`)

### 4.4.2 Implementasi CoAP
- Model request-response (UDP). Server aiocoap di laptop, resource `/sensor`, port 5683.
- ESP32 (coap-simple) kirim PUT; server balas CHANGED/OK. ✅
- Isu & solusi: pakai `put()` (bukan post), `render_put` di server, bind IP spesifik
  (Windows), buffer dinaikkan untuk payload besar. (rujuk `setup-coap.md`)

### 4.4.3 Integrasi Data dengan Kedua Protokol
- Payload JSON IDENTIK untuk MQTT & CoAP → perbandingan adil.
- Satu sumber data (1 ESP32) dikirim lewat dua protokol.

## 4.5 Implementasi Platform Monitoring (Dashboard)

Paragraf pembuka: dashboard dirancang menerima data (real-time) + status kebocoran.
Platform: Node-RED (low-code) sebagai pusat; dapat menjadi jembatan dua protokol. (rujuk `eksplorasi-dashboard.md`)

### 4.5.1 Perancangan Dashboard
- Alur Node-RED: `mqtt in` → `json` (parse) → `function` (deteksi bocor) → gauge/chart/text.
- Dashboard 2.0 (@flowfuse/node-red-dashboard): gauge Flow1/Flow2/Pressure, chart tren, teks status.

### 4.5.2 Tampilan Monitoring Data Sensor (SUDAH ADA bukti MQTT)
- Data MQTT masuk Node-RED → gauge menampilkan nilai real-time.
- Bukti: Gauge Pressure bergerak dengan data nyata (mis. ADC 305). ✅ (rujuk `setup-dashboard.md`)
- Rujuk Gambar: tampilan dashboard Monitoring.
- Catatan teknis: `nan`/`inf` harus dicegah di ESP32 agar JSON ter-parse.

### 4.5.3 Tampilan Status Deteksi Kebocoran
- Node `function` menghitung selisih Flow1−Flow2 vs threshold → status NORMAL/BOCOR
  (hijau/merah) di node text.
- Status: logika sudah disiapkan; `[ISI SETELAH PENGUJIAN]` (butuh air + kalibrasi threshold).

### 4.5.4 Integrasi CoAP ke Dashboard (dua protokol)
- Rencana: jembatan CoAP → Node-RED (node `coap in` ATAU server Python teruskan ke Node-RED).
- Status: `[BELUM DIKERJAKAN — menunggu alat]`.
